[01] What it is
— definition

Not a mock terminal. A machine.

Most "Linux on Android" apps give you a toy shell. Linuxify stages a genuine Ubuntu 24.04 LTS rootfs — the same userspace your servers run — and boots it unrooted, in app-private storage, through proot. apt works. git works. python, node, compilers and your dotfiles work.

On top of it sits a real PTY terminal (the vendored Termux emulator stack, GPLv3), a software catalog that installs tools through APT, npm, pip and checksum-pinned static binaries, project management, local servers, and a background service that keeps it all alive while you use other apps.

And it is honest about the edges: no kernel-level isolation, no privileged ports, no promise against OEM battery managers — documented, not hand-waved.

[02] Capabilities

Linuxify stages ubuntu-base 24.04.5 (arm64) — staged, resumable, checksum-verified — then self-heals the install: native-linker shims, exec-bit sweep, integrity re-checks, stale-marker repair. proot translates filesystem paths and fakes uid 0 in user space, so an unprivileged app can run an entire Linux userspace. Flaky internet is handled: HTTP-Range resume, exponential backoff with jitter, verification before anything is trusted.

proot 5.1.107.96arm64checksum-pinnedresumable

Not a web view pretending to be a shell. Linuxify vendors the Termux terminal-emulator / terminal-view stack (GPLv3, attributed): a real pseudo-terminal with tap-to-keyboard, pinch-to-zoom, extra-keys rows, long-press copy/paste on the actual Android clipboard, multiple sessions, and true scrollback. A floating button shares the whole session log to any chat or AI app in two taps.

ptymulti-sessionextra keyslog share

A foreground service with a silent persistent notification and a partial wake lock keeps the Linux userland alive while you're outside the app. When a command you left running finishes — or a session or managed service exits — a "run completed" notification tells you. Suppressed while you're actually watching. It releases itself the moment the last session or service ends.

foreground servicewake lockcompletion notify

A searchable Software catalog (System / Dev / AI / Network / Media / Data / Text) installs any tool through shared ecosystem adapters with automatic prerequisites, per-tool verification that the executable actually runs, uninstall, and honest failure reporting with recovery steps. Entries with several paths try them in preference order — jq falls back to a pinned static binary when the APT path fails. Add custom tools (apt / npm / pip, scoped npm names included), update & upgrade everything in one tap. The terminal stays unrestricted for everything the catalog doesn't know.

aptnpmpipstatic binariescustom tools

An audit checks Ubuntu version, architecture, free storage, network, package-manager health and installed tools. The package manager is repaired only when it is actually inconsistent — dpkg --configure -a, apt-get --fix-broken install — never blindly at launch. A BASE environment (curl + HTTPS certificate trust) installs by default; an optional developer profile adds git, Node.js and npm.

auditon-demand repairdev profile

Projects are first-class: clone from git, create from scratch, open straight in the terminal. Managed services serve on loopback by default; LAN exposure only ever happens by explicit choice. And the platform's limits are stated plainly — no kernel-level isolation, no privileged ports — documented, not promised away.

gitloopbacklan opt-in

Terminal sessions persist as full transcripts (scrollback + screen) with metadata; previous runs return as read-only history tabs with "new shell in this directory". One tap exports a .tar.gz through the system file picker — projects and history always, full environment optional; restore is scoped (projects / history / environment) with keep-vs-overwrite and the same hardened extractor the installer uses. Cache cleanup — per project or whole system — reports exact bytes before you confirm.

[04] How it works
step / 01

Sideload the APK

12 MB, Android 8.0+. Allow "install unknown apps" for your browser and open the APK. No account, no signup, and the SHA-256 is published with every release so you can verify what you install.

step / 02

Tap Install Ubuntu

The rootfs downloads with HTTP-Range resume, exponential backoff and checksum verification before anything is trusted. Native dependencies self-heal — you watch a log that tells the truth, not a spinner that guesses.

step / 03

Get to work

Terminal, projects, servers, catalog installs. It stays alive in the background and notifies you when long runs finish. Your files persist until you decide otherwise — and a one-tap .tar.gz backs everything up.

[05] Principles
$ local-first

Your device, your data

Files live in app-private storage on your phone. No telemetry, no analytics, no ads, no accounts. The network is used only when you trigger a download — rootfs, packages, git clones. Privacy policy.

$ honest-engineering

Verified, or not claimed

Every claim is separated into build-verified, host-verified and device-verified — and anything not labeled is not verified. Failures report recovery steps instead of hiding behind a spinner.

$ yours-to-keep

Open source, durable

Persistence until you decide otherwise; backup & restore built in. The whole source — app, runtime, docs — is GPL-3.0-or-later. Audit it, fork it, build it.

After installation, yes — everything runs locally on the device. The network is only used when you trigger it: the initial Ubuntu download, package installs, git clones, or serving to LAN on purpose. None of your data is ever sent anywhere by the app itself.

Linuxify is on an open alpha cycle. It also deliberately targets SDK 28 — Android 10+ blocks executing app-private binaries for apps targeting SDK 29+, and that execution is exactly the point of this app. The decision is documented in the source. Sideload now; distribution channels may come later.
